# Fixes 7 Execution Plan & Task Specifications

> **Crucial Rule:** Write a detailed technical implementation plan to `fixes7-plan.md` outlining specific file edits, component changes, and database migrations **before** writing any functional code.

---

## 🛠️ General Directives
* **Localization / בינאמיות:** The entire system must support both English and Hebrew. Any new UI strings, field labels, tooltips, or validation messages must be fully localized.
* **Dashboard Customization:** Any new system labels or fields must be registered and integrated with the `dashboard/localization` and `dashboard/fields` settings.
* **Database Upgrades:** All SQL database schema alterations (adding tables, rows, columns, constraints) **must** be created as sequential database migrations to guarantee data integrity and prevent any loss of production data.

---

## 1. User Access & Security: Admin Role Expansion
* **Admin Autonomy:** Existing Administrators must have the permission to provision and configure additional Admin accounts.
* **User Management View:** Update the add/edit user forms to include a role selection field supporting "Restricted User" and "Admin". Admins must inherit unconstrained global privileges across all system models and pages.
* **Google Authentication:** Connect authentication for these newly provisioned Admin users to Google Auth. Only the verified corporate/personal email identifier is strictly required to resolve identity.
* **Welcome Automation:** Upon successful setup of a new Admin profile, trigger an automated transactional welcome/onboarding email identical to the current workflow template deployed for new *Shliach* user accounts.

---

## 2. Infrastructure Refactoring: Buildings & Apartments UI
* **Inline Apartment Mutations:** Implement a seamless editing mechanism for individual apartments (e.g., an accessible action modal or inline button) mirroring the exact structural flow utilized when updating a CRM contact.
* **Building Name Constraints:** * Relax database/form constraints so that the `building_name` attribute is no longer a required field.
  * Hide the `building_name` field by default across standard entry and view panes.
  * Register `building_name` in `dashboard/fields` to enable system operators to dynamically restore its visibility on demand.
* **Canonical Display Strings:** Everywhere a building or associated location is rendered across the interface or map nodes, use the composite address pattern: `[Street Number] + [Street Name]` as the primary descriptor (e.g., *"770 Eastern Pkwy"*).
* **Address Field Validation:** Elevate the `address` attribute to a mandatory/required field across all input states.
* **Advanced Dataset Filters:** On the apartment inventory/list view, engineer robust dynamic search query controls to allow:
  * Comprehensive filtering bounded by specific `building_id`.
  * Partial-string or lookup filtering based on the `street name` inside the parent address attribute.

---

## 3. Structural Database Extensions: Floor Entities
* **New SQL Relation (`floors` / קומות):** Generate a structural migration to instantiate a dedicated database table with the following constraints:
  * `id`: Primary Key (Auto-incrementing / UUID).
  * `name`: Text/String attribute representing the floor identifier.
  * `building_id`: Foreign Key targeting the parent building entity (enforce cascading constraints where appropriate).
* **Building Creation Hook:** Enhance the building setup flow so that specifying a building structure automatically instantiates and populates its constituent floor records in the `floors` table.
* **Building Modification Interface:** Update the core building CRUD panel to expose an interface enabling operational staff to append, modify, or permanently drop records from its related floor collection.

---

## 4. Apartment Schema Refinement & Data Typing
* **Name Visibility:** De-escalate the apartment name field from mandatory status and conceal it from standard view states by default.
* **Computed Title Strategy:** Replace the standard apartment label with a dynamic alphanumeric string generated by combining the corresponding floor identifier and apartment label (e.g., *Floor 1* + *Apartment A* yields title **"A1"**).
* **Database Attribute Expansion:** Append the following fields to the apartment entity model:
  * `floor`: Text representation of the target floor level.
  * `Jewish_status` (יהדות - Picklist/Enum supporting multiple choices): `/`, `יהודי`, `יהודי מעוניין ביהדות`, `יהודי וגוי`, `יהודי מעוניין וגוי`, `יהודי שתומצ`.
  * `campaign_status` (Picklist/Enum).
  * `mezuzah_status` (נבדק / צריך בדיקה - Picklist/Enum).
  * `name`: Text representation of resident.
  * `phone`: Text field backed by the system's standard regex-based telephone validation mechanism.
  * `email`: Text field backed by standard RFC-compliant email validation rules.
* **Dynamic Picklist Management:** Expose edit, addition, and ordering configuration controls for all apartment status picklists inside `/dashboard/picklists` under a clean, unified **"Apartment" / "דירה"** subsection.
* **Field Toggle Visibility:** Expose control switches inside the global `dashboard/fields` configuration views under an **"Apartment" / "דירה"** block, mirroring the toggle capabilities available for Contacts.

---

## 5. Automation: Bulk Apartment Batch Generator
* **Batch Provisioning Dialog:** Introduce a specialized modal window onto the primary Apartments directory view.
* **Operational Criteria Selection:**
  1. A target parent **Building** dropdown selector.
  2. A multi-checkbox selection list exposing the related **Floors**.
  3. An explicit, individual discrete select array for specific target **Apartment Numbers/Letters** (explicit manual token selection rather than an inclusive index range slider).
* **Cartesian Processing Engine:** Upon execution, trigger a performant loop function that computes the full matrix (Cartesian product) of selected floors and apartment tags, batch-inserting the resulting combinations into the target storage engine via unified transactions.

---

## 6. Global Navigation Upgrades
* **Unified Navbar Search Engine:** Embed a real-time, high-performance global search entry within the persistent header layout.
  * *Behavior:* Debounced input handling executing lookups spanning Citizen/Contact names, apartment designations, building indexes, and territorial zones. Result blocks must compile dynamically as the administrator types.
  * *Verification Note:* Conduct an initial codebase discovery audit first; if a comprehensive omni-search widget is already functioning within the current environment, skip redundant implementation.

---

## 7. Geospatial Layouts: Interactive Zones & Guardrails
* **A. Region Polygon Interface:** Integrate a robust client-side map library (e.g., Leaflet or Mapbox) within the designated Areas tracking views. The view layer must fetch and render the complete spatial geometry (GeoJSON) representing all predefined territorial zones.
* **B. Geofenced Validation Interceptor:** Implement an asynchronous or runtime validation interceptor inside the building registry pipeline. When a new building address is geocoded, execute an immediate point-in-polygon verification check against the boundaries of the associated target zone. If the coordinate registers outside the zone bounds, intercept submission to throw a prominent, distinct structural safety warning to the user.

---

## 8. View Enhancements: CRM Contacts Directory Table
* **A. Tinted Row Highlighting:** Deprecate the isolated UI column reserved explicitly for displaying a contact's profile color. Transition this behavior to map the raw color data property directly to a subtle, low-opacity background tint applied uniformly across the entire table row.
* **B. High-Density Layout & Screen Utilization:** Overhaul the table container styling rules and element structures using fluid CSS principles (or custom utility classes via Tailwind). Ensure the interface stretches to utilize the complete viewport width while applying conservative column scaling. Layout properties should guarantee high information density, minimizing the need for horizontal page scrolling.
